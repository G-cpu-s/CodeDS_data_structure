Array

A collection of elements stored at contiguous memory locations, accessed instantly by index.

An array is one of the very first data structures most programmers learn, and for good reason: because its elements sit next to each other in memory, the computer can jump straight to any position using simple arithmetic instead of walking through the whole collection. That's what makes reading arr[5] just as fast whether the array has 10 elements or 10 million.

The trade-off shows up when the array needs to grow or shrink. Because the memory block is contiguous, inserting or removing an item in the middle means shifting every element after it, and if the array runs out of room, the whole thing may need to be copied into a bigger block elsewhere. Understanding this trade-off — instant access versus costly resizing — is the foundation for reasoning about almost every other data structure that follows.

Sorting

Arranging elements in a defined order — ascending or descending — using algorithms such as quicksort, mergesort, or bubble sort.

Sorting shows up almost everywhere in software — from ranking search results to preparing data for binary search — so it's usually the first place students see the trade-off between simplicity and performance. Simple algorithms like bubble sort or insertion sort are easy to write and reason about, but their O(n²) behavior makes them impractical once a dataset grows large.

Divide-and-conquer algorithms like merge sort and quicksort solve this by breaking the problem into smaller pieces, sorting those, and combining the results, bringing the average time down to O(n log n). Learning how and why these algorithms work is one of the best ways to build intuition for recursion and algorithmic complexity in general.

Bitmask

Using the bits of a number to represent and manipulate sets of flags efficiently with AND, OR, XOR, and shift operations.

A bitmask uses the individual bits inside an integer to represent a set of true/false flags — instead of eleven separate boolean variables, you can pack eleven flags into a single number and manipulate all of them at once with bitwise operators.

This technique is a favorite in competitive programming because operations like AND, OR, and XOR run in constant time directly on the CPU, making bitmasks a compact and extremely fast way to represent subsets, track visited states, or encode configuration flags.

Linked List

A sequence of nodes where each node stores data and a pointer to the next node, allowing efficient insertion and deletion.

Where an array keeps its elements in one contiguous block, a linked list scatters its nodes across memory and connects them with pointers. That difference is the whole story: a linked list can grow or shrink without ever needing to copy or shift existing data, since inserting a node is just a matter of relinking a couple of pointers.

The cost is that you lose instant indexed access — to reach the 100th node you have to walk through the 99 before it. This makes linked lists a great fit for situations with frequent insertions and deletions and a poor fit when you need fast random access.

Union Find

A structure that tracks a set of elements split into disjoint groups, supporting fast union and find operations, often with path compression.

Union Find (also called Disjoint Set) answers a deceptively simple question extremely efficiently: are these two elements in the same group? It represents a collection of items split into non-overlapping sets, and supports merging two sets together and checking which set an item belongs to.

With two small optimizations — union by size/rank and path compression — both operations run in almost constant time, which is why Union Find is the backbone of algorithms like Kruskal's minimum spanning tree and is widely used to detect cycles or track connectivity in a graph.

Fenwick Tree

A Binary Indexed Tree that allows fast prefix-sum queries and point updates, using far less memory than a full segment tree.

A Fenwick Tree, or Binary Indexed Tree, solves a common problem: repeatedly updating values in an array while also asking for the running sum of a range. A naive approach recalculates the sum every time, which gets slow fast — a Fenwick Tree instead keeps partial sums organized so that both updates and prefix-sum queries only take O(log n) time.

What makes it especially elegant is how compact it is: the structure is stored in a single array, using each number's lowest set bit to decide which other indices it's responsible for, giving segment-tree-like performance with far less code and memory overhead.

Segment Tree

A tree structure for storing information about intervals, enabling fast range queries (sum, min, max) and range updates.

A Segment Tree is built for range questions — the sum, minimum, or maximum of any slice of an array — and it answers them in O(log n) time no matter how large the range is. It works by recursively splitting the array in half, with each tree node storing the combined result for its slice, so a query only has to touch a handful of nodes instead of the whole range.

Unlike a Fenwick Tree, a Segment Tree isn't limited to sums — it can be adapted to any operation that combines two ranges, including min, max, GCD, or more complex custom operations, which makes it one of the most flexible tools for range-query problems.

Graph Traversal

Visiting all nodes of a graph using strategies like Breadth-First Search (BFS) or Depth-First Search (DFS) to explore connections.

Graphs model relationships — roads between cities, friendships in a social network, dependencies between tasks — and traversal algorithms are how you systematically explore those relationships. Breadth-First Search (BFS) explores level by level using a queue, which makes it the natural choice for finding the shortest path in an unweighted graph.

Depth-First Search (DFS) instead dives as deep as possible before backtracking, typically using recursion or a stack, and is well suited to problems like detecting cycles or exploring all possible paths. Both run in O(V + E) time and form the foundation for more advanced graph algorithms like Dijkstra's and topological sorting.

Stack

A Last-In-First-Out (LIFO) structure where the last element pushed on is the first one popped off.

A stack follows a simple rule: Last In, First Out. Whatever was added most recently is the first thing to come back out — think of a stack of plates, where you only ever add or remove from the top.

That simplicity makes stacks perfect for tracking state that needs to be undone in reverse order: function call stacks, undo history in an editor, matching parentheses, and depth-first traversal all rely on this LIFO behavior, and every core operation — push, pop, peek — runs in constant time.

Queue

A First-In-First-Out (FIFO) structure where elements are added at the rear and removed from the front.

A queue flips the stack's rule around: First In, First Out. The first element added is the first one removed, just like a line of people waiting — new arrivals join at the rear and only the person at the front gets served next.

This ordering makes queues the natural structure for anything that needs fair, in-order processing — task scheduling, printer queues, and breadth-first search all depend on a queue to make sure nothing jumps ahead of the line.

Binary Search Tree

A tree where each node's left subtree holds smaller values and its right subtree holds larger values, enabling fast lookups.

A Binary Search Tree keeps its values organized using a simple invariant: for every node, everything in its left subtree is smaller, and everything in its right subtree is larger. That single rule is what allows searching, inserting, and deleting to skip half the remaining tree at each step, similar to how binary search works on a sorted array.

On a balanced tree, this gives O(log n) performance for all three operations, but an unlucky sequence of insertions can leave the tree lopsided and degrade performance to O(n) — which is exactly the problem that self-balancing trees like AVL and Red-Black trees are designed to solve.

This course is about developing algorithmic thinking, not just memorizing code. You'll implement classic sorting algorithms like bubble sort, merge sort, and quicksort in Java, then compare their behavior directly so the trade-off between simplicity and performance becomes concrete rather than theoretical.

From there the course covers searching (linear and binary), recursion and how to reason about it, and finally greedy algorithms and dynamic programming — the techniques most commonly asked about in technical interviews. Every algorithm is paired with a time and space complexity discussion, so you build the habit of asking "how does this scale?" for anything you write.

What You'll Learn

  • Sorting algorithms and their trade-offs
  • Linear and binary search
  • Recursion and how to trace it
  • Greedy algorithms
  • Introductory dynamic programming

Course Outline

  • Module 1: Sorting algorithms
  • Module 2: Searching techniques
  • Module 3: Recursion
  • Module 4: Greedy algorithms
  • Module 5: Dynamic programming basics

C++ Fundamentals

The essential syntax and building blocks every C++ developer needs before tackling data structures and algorithms.

This course starts from zero, covering explicitly typed variables and references, core data types, and the operators used to work with them. From there it moves into control flow — conditionals and loops — and functions with pass-by-value and pass-by-reference, the two tools you'll use to structure logic in almost every program you write.

Along the way you'll get comfortable with STL containers such as vector, map, and unordered_map for grouping data, basic input and output, and reading error messages well enough to debug your own code using a compiler such as g++ alongside a debugger. By the end, you'll be able to read and write straightforward C++ programs confidently, which is the springboard for every other course in this track.

What You'll Learn

  • Variables, data types, and operators
  • Conditionals and loops for control flow
  • Writing and calling your own functions
  • Working with STL containers such as vector, map, and unordered_map
  • Basic debugging and reading error output

Course Outline

  • Module 2: Operators and control flow

Data Structures in C++

Build and use the core data structures — arrays, lists, stacks, queues, hash maps, trees, and graphs — in C++.

Once you know the basics of the language, the next step is understanding how data is organized in memory and why that organization matters. This course walks through arrays and linked lists, then stacks and queues, showing how each one is implemented using STL containers such as vector, map, and unordered_map as well as built from scratch so you understand what's happening under the hood.

From there it moves into hash-based structures like unordered_map for fast lookups, and finishes with trees and graphs, the two structures behind most real-world systems that model hierarchies or networks. Every structure is paired with the operations it supports, so you leave knowing not just how to build each one but when to reach for it.

What You'll Learn

  • Arrays and linked lists, and the trade-offs between them
  • Stacks and queues, and the problems they naturally solve
  • Hash maps for fast key-based lookups
  • Binary trees and binary search trees
  • Graph representations and basic traversal

Course Outline

  • Module 1: Arrays and linked lists
  • Module 2: Stacks and queues
  • Module 3: Hash maps and sets
  • Module 4: Trees and binary search trees
  • Module 5: Graphs and traversal basics
